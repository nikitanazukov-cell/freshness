Свежесть овощей и фруктов по фото

Полная инструкция: необходимые программы, установка, подготовка данных, обучение, локальное распознавание и проверка результатов.

В поставке — программа. Реальные фотографии и обученная на них модель добавляются в ходе выполнения работы.

Freshness NIR — оценка свежести по фотографии

Программная часть НИР: MobileNetV3-Small, три класса свежести, обучение, локальный CPU-инференс, оконный интерфейс, JSON, фотографии с подписями и отчёты.

Статус поставки: исходный код и технические тесты готовы. Реальный датасет и модель, обученная распознавать свежесть, в архив не включены. Чтобы получить такую модель, нужно добавить размеченные фотографии и выполнить обучение. Точность ≥ 75% должна быть измерена на ваших отложенных данных, а не предполагаться заранее. Технический self-test использует искусственные картинки и не является результатом НИР.

Классы всегда идут в одном порядке: FRESH, MINOR_DEFECT, SPOILED. Уверенность — максимальное значение softmax; также сохраняются оценки всех трёх классов. При confidence < 0.65 выводится предложение ручной проверки. Порог настраивается и не является медицинским или санитарным нормативом.

2. Что установить

Основной вариант: Windows 10/11, обычный 64-разрядный CPython 3.13. В установщике Python должны быть включены pip, Python Launcher и Tcl/Tk. Не выбирайте embeddable-архив или экспериментальный free-threaded Python.

Программа / компонент Обязательность Для чего
Python 3.13 x64 Да Запуск проекта
PowerShell или командная строка Windows Уже есть в Windows Команды подготовки, обучения и проверки
Tcl/Tk / tkinter Для оконного интерфейса Обычно устанавливается вместе с полным Python
Браузер Для удобного просмотра HTML Открывает сохранённые локальные отчёты
Редактор кода / IDE Необязательно Просмотр и изменение исходников
Excel или аналогичная программа Необязательно CSV; HTML доступен без Excel
GPU, CUDA, Docker, Anaconda, база данных Не нужны для CPU-варианта Не устанавливайте их ради этого проекта

Библиотеки не нужно устанавливать как отдельные приложения: установочный скрипт поставит torch, torchvision, numpy, Pillow, opencv-python-headless и albumentations. Для необязательного API дополнительно нужны FastAPI, Uvicorn и python-multipart.

В проекте согласованы torch==2.10.0 и torchvision==0.25.0. Основная установка использует CPU-сборки. Albumentations закреплена на версии 2.0.8; альтернативные аугментации torchvision тоже реализованы.

Ориентир по заданию: CPU от 4 ядер, 4 ГБ RAM минимум и 8 ГБ предпочтительно; 10–30 ГБ диска с учётом фотографий и копий выборок. Реальное время работы зависит от компьютера, разрешения фото и числа потоков.

3. Установка в Windows

Распакуйте весь архив, например в C:\Projects\Freshness_NIR. Не запускайте файлы прямо внутри ZIP.

Самый простой способ — двойной щелчок по install_windows.bat. Он создаёт .venv, устанавливает CPU-библиотеки и выполняет doctor. Для первоначальной установки нужен интернет.

Ручной вариант, из PowerShell в папке проекта:

py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py doctor

Мы обращаемся непосредственно к Python внутри .venv; запускать Activate.ps1 и менять политику безопасности PowerShell не требуется.

При использовании обычного Python 3.11 или 3.12 замените только первую команду, например на py -3.12 -m venv .venv. Автоматический .bat ориентирован именно на 3.13. Проверки в поставке выполнены на Python 3.13.5/Linux, а не на вашем Windows-компьютере.

4. Сначала проверить программу без настоящего датасета

.\.venv\Scripts\python.exe main.py self-test

Команда сама создаст небольшие искусственные картинки, разделит их, выполнит две тренировочные эпохи и проверит весь путь до JSON, CSV, HTML, изображений с подписями и измерения скорости.

Результаты будут в outputs/self_test. Модель из этой папки помечена smoke_test=True; её нельзя использовать в качестве модели свежести или предъявлять её accuracy как результат исследования. Итоговая исследовательская приёмка для неё всегда False.

По умолчанию self-test использует аугментации torchvision. После установки Albumentations можно отдельно проверить второй движок:

.\.venv\Scripts\python.exe main.py self-test --augmentations albumentations --output outputs/self_test_albumentations

Повторный запуск в непустую папку запрещён: выберите другое имя --output.

5. Подготовить реальные фотографии

В архиве уже есть пустые каталоги:

data/raw/
    FRESH/
    MINOR_DEFECT/
    SPOILED/

Разложите реальные фото по этим трём классам. Минимальный ориентир задания — 30–40 фотографий на класс; это не гарантия качества. Каждый из выбранных 3–4 видов продукта желательно представить во всех трёх состояниях.

Несколько ракурсов одного плода — одна группа. Используйте вложенную папку с уникальным ID образца:

data/raw/FRESH/apple_001/front.jpg
data/raw/FRESH/apple_001/back.jpg
data/raw/MINOR_DEFECT/apple_002/front.jpg
data/raw/SPOILED/tomato_003/front.jpg

Если тот же плод сфотографирован через несколько дней в другом состоянии, сохраняйте прежний ID папки в новом классе. apple_001 во всех классах попадёт в одну часть выборки. Не называйте такую папку просто apples, если внутри множество независимых яблок.

Альтернатива без вложенных папок: apple_001__front.jpg, apple_001__back.jpg. Префикс до __ — ID образца. Одиночные фото можно класть прямо в папку класса.

Для ручной разметки через окно сначала поместите неразмеченные снимки в отдельную папку, например data/inbox, затем:

.\.venv\Scripts\python.exe main.py label --input data/inbox

В окне выбирайте класс и при необходимости указывайте ID плода. Оригиналы не удаляются: создаются копии в data/raw.

Полные правила разметки, ограничения Kaggle-набора и предотвращение утечек описаны в docs/DATASET_RU.md.

6. Разделить данные

.\.venv\Scripts\python.exe main.py prepare
.\.venv\Scripts\python.exe main.py audit

Получится:

data/prepared/
    train/FRESH/ ...
    val/FRESH/ ...
    test/FRESH/ ...
    manifest.csv
    split_summary.json

В каждой части присутствуют все три класса. Доли примерно 70/15/15; они могут отличаться, потому что целый плод нельзя делить между выборками. Точные дубликаты удаляются. Похожие, но не идентичные снимки автоматически не распознаются как один плод — для них важны корректные ID групп.

После изменения исходных фотографий создавайте новую подготовленную папку, например:

.\.venv\Scripts\python.exe main.py prepare --output data/prepared_v2

Исходные фото не удаляются и не перезаписываются.

7. Обучить модель

Стандартный запуск:

.\.venv\Scripts\python.exe main.py train --epochs 25

При первом таком запуске torchvision скачает веса ImageNet, если их ещё нет в локальном кэше. Это веса общего распознавания изображений, а не готовая модель свежести. Затем программа заменит последний слой на три выхода и дообучит модель.

Первые 3 эпохи обучается классификатор, остальные — также свёрточная часть. По умолчанию AdamW, batch size 16, разные learning rate для головы и основы, аугментации Albumentations, фиксированный seed 42. Лучшая модель выбирается по validation macro-F1; test для выбора модели не используется.

На менее мощном компьютере:

.\.venv\Scripts\python.exe main.py train --epochs 25 --batch-size 8 --threads 2

Явная альтернатива при проблемах с Albumentations: установите основные зависимости из requirements-core.txt (CPU-пара torch/torchvision — как выше) и выполните:

.\.venv\Scripts\python.exe main.py train --epochs 25 --augmentations torchvision

Наборы преобразований близки по смыслу, но не идентичны. Выбранный движок записывается в конфигурацию опыта.

После обучения:

models/freshness/
    best.pt
    config.json
    dataset_audit.json
    history.csv
    history.json
    training_summary.json
    training.html

Откройте training.html: там история, график accuracy и метрики лучшей validation-модели. Это не финальный test-результат.

Для нового эксперимента используйте новую папку:

.\.venv\Scripts\python.exe main.py train --output models/experiment_02 --epochs 30

Проект не перезаписывает непустые папки экспериментов и не реализует продолжение обучения с оптимизатором. После прерывания уже сохранённый best.pt остаётся пригодным для инференса.

8. Измерить качество на test и скорость CPU

.\.venv\Scripts\python.exe main.py evaluate
.\.venv\Scripts\python.exe main.py benchmark --input data/prepared/test --repeats 100

В outputs/test/report.html находятся accuracy, macro-F1, метрики классов, матрица ошибок и таблица всех тестовых фото. Подписи на изображениях сохраняются для первых 15 тестовых примеров; JSON и строки таблицы — для всех.

outputs/test/summary.json содержит вычисленные флаги приёмки. Проект использует более строгую конкретизацию требования времени: P95 полного pipeline ≤ 200 мс на CPU. Pipeline включает чтение/декодирование, подготовку тензора, вызов модели и получение ответа. Не включает загрузку модели, прогрев, сохранение файлов и отрисовку GUI. Время модели отдельно тоже записывается.

outputs/benchmark.json показывает среднее, медиану и P95 по повторным измерениям. Повторное чтение может использовать файловый кэш ОС. Значения на вашем компьютере нужно измерить; они не зашиты в код.

Test запускайте для итогового подтверждения, а не для подбора параметров после каждого изменения. Для подбора служит validation. Дополнительный интервал Уилсона в отчёте рассчитан по фотографиям при предположении независимых наблюдений; он не учитывает корреляцию ракурсов одного плода и ошибки разметки.

9. Пользоваться оконным приложением

Запустите start_gui.bat или:

.\.venv\Scripts\python.exe main.py gui

Выберите models/freshness/best.pt, затем фотографию и нажмите «Распознать фото». Будут показаны класс, confidence и вероятности всех классов. Результат, JSON и отчёт сохраняются в отдельный каталог outputs/gui/....

Кнопка «Обработать папку» распознаёт несколько снимков. Флажок «Папка размечена по классам» включайте только для структуры с подкаталогами FRESH, MINOR_DEFECT, SPOILED. Тогда в отчёте появятся «Правильно» и «Ошибка». Без истинных меток программа не может честно определить правильность собственного ответа.

В GUI реализованы распознавание и пакетная обработка. Обучение и оценка test запускаются из командной строки.

10. Демонстрация 10–15 фото и запуск без GUI

Разложите 10–15 новых размеченных фото в data/demo/FRESH, data/demo/MINOR_DEFECT, data/demo/SPOILED. Они не должны участвовать в обучении.

.\.venv\Scripts\python.exe main.py predict --input data/demo --labeled --limit 15 --output outputs/demo

При лимите снимки выбираются попеременно из классов, а не только из первого по алфавиту. Откройте outputs/demo/report.html. Для защиты подготовлены таблица, JSON и изображения с подписями.

Один файл:

.\.venv\Scripts\python.exe main.py predict --input "C:\Photos\apple.jpg" --output outputs/single_01

Произвольная неразмеченная папка:

.\.venv\Scripts\python.exe main.py predict --input "C:\Photos\new_products" --output outputs/batch_01

В каждом результате: class, class_ru, confidence, probabilities, needs_review, измеренные времена и SHA-256 файла модели. CSV записывается с UTF-8 BOM для Excel; разделитель — запятая. При необходимости используйте в Excel импорт «Из текста/CSV».

11. Работа без интернета

После установки зависимостей и обучения команды predict, gui, evaluate, benchmark и локальный API не скачивают модели. Веса для инференса читаются только из указанного .pt.

Для обучения без сети заранее, пока интернет доступен, выполните:

.\.venv\Scripts\python.exe main.py cache-weights

Затем передайте локальный файл явно:

.\.venv\Scripts\python.exe main.py train --initial-weights models/imagenet_mobilenet_v3_small.pth

Для переноса на другой компьютер нужны исходники, установленная совместимая Python-среда и best.pt; для продолжения экспериментов также данные. Простое копирование .venv между разными компьютерами не рекомендуется.

12. Необязательный API

Этот раздел можно пропустить: весь основной функционал работает без сервера.

.\.venv\Scripts\python.exe -m pip install -r requirements-api.txt
.\.venv\Scripts\python.exe main.py serve

Откройте в браузере http://127.0.0.1:8000. Форма работает локально и не использует внешние CDN. Запрос: POST /predict, поле multipart file; ответ — JSON. GET /health проверяет готовность.

Пример Windows:

curl.exe -X POST -F "file=@C:\Photos\apple.jpg" http://127.0.0.1:8000/predict

Сервер привязан к 127.0.0.1. Не публикуйте его в интернете: аутентификация и производственная защита не входят в учебный проект. Остановка — Ctrl+C. Время в API-ответе не включает HTTP-передачу и декодирование файла; для приёмки используйте benchmark/evaluate.

13. Ограничения и важные уточнения

Модель оценивает визуальные признаки, а не пригодность пищи к употреблению. Она не измеряет запах, мягкость на ощупь, микробиологическую безопасность или скрытую порчу. Даже высокий confidence не гарантирует правильный ответ. На фото должен быть один отчётливо видимый продукт либо однородная группа; поиск объектов, сегментация и распознавание вида продукта не реализованы.

Третий класс MINOR_DEFECT требует настоящей человеческой разметки. Нельзя заменить его случайными фото из rotten или просто искусственно размытыми изображениями.

В формулировке задания «MobileNetV3-Small, ~2,5 МБ» неточность: стандартная ImageNet-модель имеет около 2,54 млн параметров и файл весов около 9,8 МБ по документации torchvision. После замены последнего слоя в этом проекте — 1 520 931 параметр и около 6,2 МБ для FP32-checkpoint с метаданными. Квантование до INT8 не реализовано; размер 2,5 МБ не обещается.

Архив не содержит сторонних датасетов, библиотек, шрифтов или готового научного результата. Подробности реализации: docs/METHOD_RU.md; устранение ошибок: docs/TROUBLESHOOTING_RU.md; реально выполненные проверки и непроверенные режимы: docs/TEST_REPORT_RU.md.

Данные, разметка и корректный эксперимент

Что именно размечаем

В этой задаче метка относится к состоянию продукта, а не к его виду.

Метка Рабочее описание для НИР
FRESH Нет явных видимых дефектов в пределах выбранных правил разметки
MINOR_DEFECT Видимый небольшой локальный дефект, без выраженной плесени и обширного разрушения
SPOILED Выраженные видимые признаки порчи, например плесень или обширное разрушение тканей

Это учебные визуальные категории, а не заключение о безопасности еды. Желательно заранее согласовать границу MINOR_DEFECT/SPOILED с руководителем и сохранить правила разметки в отчёте. Потемнение банана, механическая царапина и плесень — разные явления; нельзя автоматически считать любое тёмное пятно одинаковой степенью порчи.

Мягкость на ощупь и запах не видны непосредственно на фотографии. Если метка основана на этих свойствах, модель может не иметь достаточно визуальных данных для её воспроизведения.

Сколько нужно фотографий

В задании задан ориентир 30–40 фото на класс и 3–4 вида продуктов. Для старта это примерно 90–120 уникальных фото суммарно. Наличие такого числа кадров не гарантирует accuracy 75%. Важны независимые плоды, а не множество почти одинаковых снимков одного экземпляра.

Постарайтесь представить каждый вид продукта во всех состояниях, а также разные фоны, освещение, положения и масштабы. Иначе модель может выучить вид продукта или фон вместо свежести. Отдельно подготовьте 10–15 новых фотографий для демонстрации.

Kaggle и третий класс

Набор из условия называется Fruits fresh and rotten for classification, автор Sriram Reddy Kalluri. Он ориентирован на fresh/rotten для яблок, бананов и апельсинов; не следует считать его готовым размеченным набором ровно для трёх стадий из задания.

Карточка: https://www.kaggle.com/datasets/sriramr/fruits-fresh-and-rotten-for-classification

Порядок работы с внешним набором:

  1. Скачайте его самостоятельно через Kaggle и проверьте условия использования. Пароли и API-токены проекту не нужны.
  2. Просмотрите изображения. Для MINOR_DEFECT отберите и размечайте реальные подходящие случаи либо дополните набор собственными снимками.
  3. Не считайте «unripe», «ripe», «stale» или все изображения «rotten» автоматическими синонимами MINOR_DEFECT: это разные определения.
  4. Сгруппируйте готовые аугментации и похожие ракурсы по исходному изображению/плоду. При недоступных ID предпочитайте независимый собственный test.
  5. Поместите итоговую ручную разметку в data/raw и выполните prepare.

Проект не скачивает Kaggle автоматически, не обходит авторизацию, не переименовывает исходные классы без проверки и не создаёт третий класс искусственным размытием.

Структура групп

Предпочтительный вариант:

data/raw/
    FRESH/
        apple_001/
            front.jpg
            back.jpg
        banana_002/
            front.jpg
    MINOR_DEFECT/
        apple_003/
            front.jpg
    SPOILED/
        banana_004/
            front.jpg

Все имена первого уровня внутри папки класса трактуются как ID отдельных образцов, а не как категории вида продукта. Идентификатор общий для всех классов: если один и тот же apple_001 позже испортился, его новые снимки в другом классе остаются той же группой.

В плоском варианте разделитель __ отделяет ID группы: apple_001__front.jpg. Без вложенной папки и без __ каждый файл считается независимым, кроме найденных точных дубликатов.

Как программа предотвращает утечки

prepare читает фото с учётом EXIF, переводит в RGB и вычисляет SHA-256 декодированных пикселей. Полные совпадения одного класса объединяются. При одинаковой картинке с разными метками подготовка останавливается. Если одинаковые кадры связывают две группы, группы тоже объединяются.

Сначала делятся группы, а уже внутри обучения на лету применяются аугментации. Все классы должны присутствовать в train, val и test. Для одного класса технически нужно не менее трёх независимых групп; этого недостаточно для содержательного исследования.

Хеш не обнаруживает все почти одинаковые картинки: изменение JPEG-сжатия, небольшой поворот или иной ракурс меняют пиксели. Поэтому корректные ID групп остаются обязательными для серий снимков.

manifest.csv фиксирует относительный путь, часть выборки, класс, ID группы, хеш и исходный путь. audit проверяет наличие файлов, изменение пикселей, лишние файлы и пересечение групп между частями. train и evaluate вызывают аудит автоматически.

Что не делать

Не переносите тестовые фото в обучение после неудачного результата. Не подбирайте эпохи, аугментации или порог по test. Не выдавайте качество на искусственных картинках self-test за качество на продуктах. Не размечайте новый снимок предсказанием той же модели и затем не используйте его как независимое подтверждение её правильности.

Параметры подбираются по validation. Итоговая модель оценивается на test. Демонстрационные фото служат показом работы и не заменяют нормальную тестовую выборку.

Как устроена программа

1. Путь изображения

read_rgb() открывает файл, применяет ориентацию EXIF и получает RGB-массив. Неподдерживаемые и повреждённые изображения вызывают понятную ошибку. Кириллические пути поддерживаются. Очень большие изображения ограничены 40 млн пикселей для защиты от случайного чрезмерного расхода памяти.

OpenCV масштабирует фото до квадрата 224×224 с сохранением пропорций. Свободная область заполняется нейтральным серым. Вместо центрального обрезания выбран letterbox, чтобы не отрезать пятна на краях.

Во время обучения применяются горизонтальный разворот, небольшие повороты, умеренные изменения яркости/контраста и редкое размытие. Для validation, test и реального инференса случайных преобразований нет. Во всех режимах используются одинаковые mean/std ImageNet: (0.485, 0.456, 0.406) и (0.229, 0.224, 0.225).

2. Модель и обучение

Исходная архитектура — torchvision.models.mobilenet_v3_small. Оригинальный последний Linear со 1000 выходами заменяется на Linear с тремя выходами. Остальная структура сохраняется. Итоговое число обучаемых и временно замороженных параметров вместе — 1 520 931.

По умолчанию используются веса MobileNet_V3_Small_Weights.DEFAULT из ImageNet. На первых трёх эпохах заморожена свёрточная часть, затем она тоже дообучается. Для небольших minibatch статистики BatchNorm по умолчанию фиксированы; это можно изменить --train-batchnorm.

Оптимизатор AdamW: learning rate классификатора 0.001, свёрточной части 0.0001, weight decay 0.0001. Скорости плавно снижаются по косинусной схеме. CrossEntropyLoss получает исходные logits, а не уже вычисленный softmax. Веса классов рассчитываются только по train для уменьшения влияния дисбаланса. Градиенты ограничиваются по норме.

seed=42 задаётся для Python, NumPy, PyTorch и Albumentations. DataLoader использует num_workers=0, что упрощает запуск Windows и воспроизводимость. Это не обещание побитно одинакового результата на разном оборудовании и разных версиях библиотек.

3. Выбор лучшей модели

После каждой эпохи выполняется validation. Критерий выбора — macro-F1, при равенстве accuracy, затем меньший loss. Test не используется для выбора checkpoint.

Checkpoint содержит state_dict, порядок классов, настройки предобработки, параметры обучения, версии PyTorch/torchvision, validation-метрики и fingerprint подготовленного датасета. Обучение сохраняет только веса для инференса, а не полный optimizer state; продолжение прерванного обучения с тем же состоянием оптимизатора не реализовано.

При загрузке проверяются версия формата, архитектура, классы и предобработка. Используется torch.load(..., weights_only=True). Загружайте только доверенные файлы моделей: этот параметр не делает любой посторонний файл безопасным.

4. Результат распознавания

Модель возвращает три logits. Из них вычисляется softmax; класс соответствует максимуму, confidence — его значению. Сумма трёх оценок примерно равна 1.

Высокий softmax сам по себе не доказывает правильность. Калибровка вероятностей и полноценное обнаружение неизвестных объектов в проект не включены. Порог ручной проверки 0.65 — настраиваемый вспомогательный параметр, не подтверждённый универсальный порог качества.

Фото стула или неизвестного вида продукта тоже получит один из трёх классов. Программа не является детектором «фрукт/не фрукт». Пользователь должен соблюдать область применения модели.

5. Метрики и измерение времени

Accuracy — доля правильных предсказаний. Precision показывает долю верных ответов среди предсказаний класса, recall — найденную долю истинных объектов класса. F1 объединяет precision и recall. Macro-F1 усредняет F1 трёх классов, не отдавая автоматически преимущество многочисленному классу.

В матрице ошибок строки соответствуют истинному классу, столбцы — предсказанному. Основные критерии задания проверяются по accuracy на test и скорости CPU. Дополнительные метрики помогают увидеть, например, систематическое смешение MINOR_DEFECT и SPOILED.

Измерения идут с eval() и torch.inference_mode(), после прогрева, с batch size 1. Отдельно фиксируются чтение, подготовка, модель и полный pipeline. Итоговый порог — P95 pipeline ≤ 200 мс. Загрузка checkpoint, прогрев и запись подписанных файлов в этот показатель не входят.

6. Сохранение и интерфейсы

Для каждого фото сохраняется JSON. Для партии — общий JSON, CSV и автономный HTML. Подписи рисуются Pillow; используются встроенные символы и английские имена классов, поэтому проект не раздаёт сторонние шрифты.

Tkinter-интерфейс выполняет длительную обработку в рабочем потоке, а обновления виджетов — в основном потоке через очередь. API по умолчанию доступен только на localhost и использует ту же модель и предобработку.

Главное ограничение остаётся содержательным: распознаются видимые признаки в пределах обучающего распределения, а не санитарная пригодность продукта.

Частые проблемы

Нет Python или команда py не найдена

Установите полный обычный Python 3.13 x64 с Python Launcher, pip и Tcl/Tk. После установки заново откройте PowerShell. Проверка: py -3.13 --version.

Если уже используете другой обычный Python 3.11/3.12, создайте .venv вручную этим интерпретатором, затем выполните команды установки из README. .bat выбирает именно Python 3.13.

Не используйте 32-разрядный, embeddable или free-threaded вариант для этой инструкции.

PowerShell блокирует Activate.ps1

Активация не требуется. Все команды в README обращаются к .\.venv\Scripts\python.exe напрямую. Менять ExecutionPolicy не нужно.

ModuleNotFoundError

Устанавливайте зависимости тем же Python, которым запускаете проект:

.\.venv\Scripts\python.exe -m pip install -r requirements.txt

Для сервера API отдельно установите requirements-api.txt. Сам API не нужен для оконного приложения.

Ошибка torchvision, несовместимый torch или operator torchvision::nms does not exist

Используйте согласованную пару torch 2.10.0 / torchvision 0.25.0 и одинаковый тип сборки. В изолированной среде проекта переустановите оба CPU-пакета:

.\.venv\Scripts\python.exe -m pip install --force-reinstall torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe main.py doctor

Это инструкция для CPU-варианта, не для сохранения собственной GPU-среды.

Albumentations не установилась

Сначала прочитайте фактическую ошибку pip: причина может быть в сети или неподходящем Python. Проект также поддерживает явную альтернативу:

.\.venv\Scripts\python.exe -m pip install -r requirements-core.txt
.\.venv\Scripts\python.exe main.py train --augmentations torchvision

Для этого режима достаточно requirements-core.txt; CPU-пара torch/torchvision устанавливается как в README. Все основные преобразования предусмотрены и в этом режиме. Для стандартного варианта задания установите Albumentations и используйте режим по умолчанию. В поставке CPU-тесты выполнены с torchvision; Albumentations в среде проверки недоступна.

Нет models/freshness/best.pt

Это нормально до первого обучения. Последовательность: настоящие фото → prepare → train → evaluate/gui. В архиве нет готовой модели свежести.

Файл ImageNet .pth не подходит для GUI: это инициализация обучения, а не трёхклассовый checkpoint проекта. Модель self-test предназначена только для проверки программы.

Empty class / неизвестные папки классов

Нужны ровно FRESH, MINOR_DEFECT, SPOILED, с тем же регистром и подчёркиванием. В каждой должны быть изображения. Каталоги freshapples и rottenbanana не являются нужной структурой и не содержат автоматически третью стадию.

Не хватает независимых групп

Не менее трёх групп на класс нужны технически для train/val/test. Для исследования нужно существенно больше. Десятки фото одного плода не заменяют независимые образцы.

Если все яблоки лежат в папке FRESH/apples, она трактуется как один образец. Разнесите по уникальным ID: apple_001, apple_002 и т.д.

Папка уже содержит файлы

Программа специально не удаляет предыдущие результаты. Укажите новую папку --output, например outputs/demo_02 или models/experiment_02. Для нового prepared-набора не забывайте передать его путь в последующие train и evaluate.

Manifest не совпадает / изображение изменено

После подготовки нельзя вручную менять картинки в data/prepared. Исправьте исходный data/raw и выполните prepare в новую папку. Затем обучите соответствующую модель. Для новых независимых демонстрационных снимков используйте predict --labeled, а не подменяйте исходный test.

Обучение медленное или не хватает RAM

Уменьшите --batch-size до 8 или 4. Для inference/benchmark сравните --threads 1, 2, 4; больше потоков не обязательно быстрее. GPU не требуется. Для CUDA нужны подходящие GPU-драйверы и CUDA-сборка PyTorch, после чего можно использовать train --device cuda; стандартный установщик ставит CPU-сборку.

Accuracy ниже 75%

Не меняйте числа в отчёте. Проверьте качество разметки, достаточность независимых плодов, баланс классов и представленность видов продукта во всех состояниях. Посмотрите матрицу ошибок на validation. Подбирайте параметры по validation, а test сохраняйте для итоговой проверки.

При маленьком наборе ошибка даже на нескольких снимках сильно меняет accuracy. Высокая оценка на похожих фотографиях одного плода не означает хорошего качества на новых продуктах.

GUI не запускается / No module named tkinter

Для полного Python Windows включите компонент Tcl/Tk. Проверка:

.\.venv\Scripts\python.exe -m tkinter

В Linux GUI требует установленного tkinter и графической сессии. CLI, обучение и отчёты могут использоваться без окна.

CSV открывается одной колонкой

В Excel используйте импорт «Из текста/CSV», UTF-8, разделитель «запятая». Или откройте report.html — Excel вообще не нужен.

Полный текст ошибки

Укажите --debug перед названием команды:

.\.venv\Scripts\python.exe main.py --debug train --epochs 25

Ошибка прерывает команду с ненулевым кодом завершения. Уже сохранённые файлы автоматически не удаляются.
